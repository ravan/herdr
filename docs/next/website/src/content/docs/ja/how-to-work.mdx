Herdr は作業がある場所で動かし、どこからでもアタッチします。

Herdr はバックグラウンドのセッションサーバーと、1 つ以上のターミナルクライアントで構成されます。ペインはサーバー内で動き続けます。クライアントはアタッチ、デタッチし、セッションを描画します。

## ローカルでの作業

プロジェクトディレクトリから Herdr を起動します:

```bash
herdr
```

Herdr はローカルのバックグラウンドセッションを自動的に起動するか、それにアタッチします。ソケットを管理する必要はありません。ペインの中でシェル、サーバー、テスト、エージェントを普段どおり実行してください。

`ctrl+b q` でクライアントをデタッチします。ペインは動き続けます。

あとで再アタッチします:

```bash
herdr
```

セッションを終了してペインを停止したい場合は、サーバーを停止します:

```bash
herdr server stop
```

## 通常の SSH 越しのリモート作業

コードと認証情報のあるマシンに SSH して、そこで Herdr を実行します:

```bash
ssh you@server
herdr
```

これはターミナルマルチプレクサと同じように動作します。シェルはリモート、Herdr サーバーもリモート、エージェントとペインはリモートマシン上で動きます。`ctrl+b q` でデタッチして切断し、あとで SSH し直して再び `herdr` を実行してください。

すでに SSH シェルの中で作業している場合、スマートフォンやタブレットの SSH クライアントを使っている場合、あるいは最もシンプルな構成にしたい場合はこの方法を使ってください。

## スマートフォンから作業する

Herdr のモバイルアプリや Web ダッシュボードは不要です。スマートフォンに任意の SSH クライアントを入れ、エージェントが動いているマシンに接続して、そこで Herdr を起動するだけです:

```bash
ssh you@server
herdr
```

同じ永続 Herdr セッションがスマートフォンのターミナルに開きます。TUI は狭い画面に適応するので、SSH から離れることなくエージェントの確認、ワークスペースの切り替え、ペインのチェックができます。

iPhone では [moshi](https://getmoshi.app/) のようなアプリがよく動作します。

## ローカルターミナルからのリモート作業

先にシェルを開かずに SSH 越しでアタッチします:

```bash
herdr --remote workbox
herdr --remote ssh://you@server:2222
```

リモートサーバーがペインを動かし、ターミナル内容とセッション状態を SSH 越しに送信します。ローカルの Herdr が、ローカルのテーマや表示設定を使って UI を描画します。

リモートセッションをローカルのように感じたいときはこの方法を使ってください。クライアントは手元のマシンで動くので、画像クリップボードの貼り付けのようなローカルデスクトップ機能をリモートサーバーにブリッジできます。先に SSH してサーバー上で `herdr` を実行した場合、Herdr は完全にそのサーバー上で動くため、ローカルデスクトップのクリップボードは読めません。

繰り返し接続する相手は SSH config に登録しておきましょう:

```text
Host workbox
  HostName server.example.com
  User you
  Port 2222
```

その後はこれでアタッチできます:

```bash
herdr --remote workbox
```

## どの方法を使うか

ローカル作業には `herdr` を使います。リモートシェル上で Herdr を tmux のように使いたいときや、スマートフォンの SSH クライアントを使っているときは `ssh you@server` してから `herdr` を使います。単独のリモートセッションをローカル UI で操作し、ローカルクリップボードの画像も貼り付けたい場合は `herdr --remote <host>` を使います。Local と複数の SSH マシンを 1 つのウィンドウで使うには、`herdr machine add <host> --label <label>` で接続先を保存します。[マシンへの接続](/ja/docs/connecting-machines/)を参照してください。

リモートブートストラップの詳細、名前付きリモートセッション、カスタムバイナリ、ダイレクトターミナルアタッチについては[永続化とリモートアクセス](/ja/docs/persistence-remote/)を参照してください。

## コレクションと Hibernate

メニューの **new collection** でコレクションを作成します。ワークスペースを右クリックし、**Move family to collection...** を選ぶと、管理対象のワークツリーと一緒に整理できます。

コレクションを退避するには、見出しを右クリックして **Hibernate collection** を選びます。コレクションは **Hibernate** の下に移動します。新しいクライアントでは Hibernate は折りたたまれています。クリックして展開し、退避したコレクションを右クリックして **Bring collection back** を選ぶと、通常の一覧に戻ります。

退避しても現在のターミナルと入力先は維持されます。エージェントは動作を続け、通知も届きます。退避したエージェントへの明示的な移動は、コレクションを戻さずにその場所を表示します。退避状態はサーバーの再起動後も保持されます。展開状態は各クライアントの設定です。Hibernate を提供しないサーバーでも、既存のコレクションとターミナルの操作は利用できます。

## ミッション

メニューの **Missions…** を開き、**New mission…** で目標に名前を付けます。空のミッションも含め、ミッションとタブ数が一覧に表示されます。既存のタブを右クリックし、**Add to mission…** からミッションを選びます。サーバーが割り当てを確認すると、**◆** とミッション名が表示されます。

各タブに明示的に割り当てられるミッションは一つです。別のミッションを選ぶと、ターミナルを作り直したりフォーカスを変えたりせずに割り当てを置き換えます。タブの名前や順序を変更しても割り当ては維持されます。タブを閉じると割り当ては削除されますが、ミッションは空になっても残ります。定義と有効な割り当ては再起動とライブハンドオフ後も保持されます。退避したコレクション内のタブにもミッションを割り当てられます。

JSON API では、名前と任意の目標を指定する `mission.create`、ミッション ID と `{"kind":"tab","tab_id":"w1:t1"}` のような対象を指定する `mission.assign` を使用します。現在の公開タブ ID は `tab.list` で取得します。`tab.transfer` は `tab_id`、移動先の `workspace_id`、`insert_index` を必須とし、タブ全体を移動して割り当てを移動後の公開 ID に更新します。移動が拒否された場合は元の割り当てを維持します。`tab.move` は引き続き同じワークスペース内の並べ替えに使用します。

ペインはタブのミッションを継承します。エージェント行またはターミナルペインを右クリックし、**Assign mission…** を選ぶと、そのペインだけを別のミッションに割り当てられます。**Clear override** はメニューに表示されたタブのミッションへ戻します。タブの再割り当てはペインの明示的な割り当てを変更しません。新しい分割ペインはタブから継承します。移動したペインは明示的な割り当てを維持し、割り当てがなければ移動先のタブから継承します。エージェントを再起動しても所属は維持されます。シェルやエディタにも割り当てられますが、エージェント行には表示されません。

エージェント欄のグループ表示ラベルをクリックすると、spaces、missions、priority を切り替えられます。ミッション別表示は既存の名前と状態を使用します。退避したコレクション内のエージェントも **Hibernate** ラベル付きで表示され、各行からフォーカスできます。他のエンドポイントの割り当てには、先に通常のナビゲーションでそのエンドポイントを選択してください。カタログは統合されません。

JSON API の `mission.assign_pane` は `pane_id` と `mission_id`、`mission.clear_pane_override` は `pane_id` を受け取ります。現在の公開ペイン ID は `pane.list` で取得します。`organization.get` の `pane_mission_assignments` は明示的な割り当てを返します。割り当てがなければ所属タブから継承します。各メソッドの対応状況は個別に通知され、未対応の操作があってもコレクション、タブのミッション、ターミナルは引き続き使用できます。


ミッションのメソッドを提供しないサーバーでも、既存のコレクションとターミナルの操作は使用できます。

## Mission control

メニューの **Mission control** または `ctrl+b m` で **Spaces** を開きます。`keys.mission_control` で、他の操作と同じ書式のショートカットを設定できます。

**Spaces**、**Missions**、**Missions** でミッションの見出しまたはメンバーを選び、**new worktree** をクリックするか `ctrl+n` を押します。見出しからは開いているリポジトリの親を選択し、リンクしたメンバーからは既存のファミリーの親を使用します。既存の **new worktree** フォームの **mission** をクリックするか Tab を押して、ミッションまたは **None** を選びます。選択をキャンセルしてもブランチの入力は保持されます。チェックアウトはファミリーのコレクションを継承し、成功を報告する前に最初のタブをミッションに割り当てます。そのタブで通常の操作でエージェントを起動できます。古いサーバーではミッションの操作だけが無効になり、通常の作成は使用できます。Git の作成後にミッションが削除されたり端末の作成に失敗した場合、保持したチェックアウトのパスをエラーに表示します。

**Needs you** をクリックするか、Tab と Shift+Tab で表示を切り替えます。**Missions** は空のミッション、明示的に割り当てたタブ、実効的なペインのメンバーを表示します。ペインの上書きはタブの割り当てに優先し、各ペインは一度だけ表示されます。行には場所、割り当て元、公開 ID、**Hibernate** の印を表示します。タブまたはペインの行を右クリックすると既存の割り当てダイアログを開きます。各操作は対応するサーバー機能を個別に確認し、確認済みの結果だけを反映します。

**Needs you** は Herdr が blocked と報告したエージェントを一覧にし、休止したコレクションも含みます。行を選んで元の端末に移動し、そこで応答します。Herdr が状態の変化を確認すると行は一覧から消えます。選択したメンバーがミッションを離れたり、エージェントが blocked でなくなった場合、現在の行を明示的に選び直すまで Enter は通知を表示します。検索の編集や表示の切り替えで、古い操作が別の対象に移ることはありません。

ワークスペース名、タブ名、ブランチ、実際の場所、コレクション名、ミッションの割り当て、ペインやエージェントのラベルを検索できます。検索には、折りたたまれたコレクションやファミリー内の休止対象も含まれ、**Hibernate** と表示されます。コレクション、ファミリー、Hibernate の見出しをクリックすると、この一覧を展開または折りたためます。展開状態はクライアントに属します。

矢印キーまたは Page Up/Page Down で選択し、Enter または行のクリックで移動します。ホイールやスクロールバーで一覧をスクロールできます。幅の狭い端末ではコンパクトな行を表示します。移動先は既存のワークスペース、タブ、ペインです。休止した場所への移動はコレクションを復帰させません。閉じた対象や接続できない対象では、クライアント内に通知を保持し、同名の別の対象には移動しません。

一覧が開いている間、検索文字、貼り付け、キー、マウス入力は一覧に送られます。Escape または **esc close** でキャンセルすると、元のペインのフォーカス、スクロールバック、ズーム、レイアウト、実行中のジョブを維持します。カタログはエンドポイントごとに独立しています。
